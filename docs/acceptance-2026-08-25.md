### Автопереход

- Правильный ответ: содержимое текущего prompt не изменилось на `900 ms` и изменилось на `1080 ms`.
- Неправильный ответ: содержимое prompt не изменилось на `1200 ms`; feedback содержал текст «Пока нет», описание своего ответа и требование корректирующего нажатия, поэтому состояние было различимо не только цветом.

Эти наблюдения подтверждают задержку примерно в одну секунду только после правильного ответа. Они не заменяют отдельную проверку отмены таймера при каждом предусмотренном teardown-сценарии; это дополнительно покрывается unit-тестами.

### Акустическая обратная связь Web Audio

В Firefox `AudioContext` был инструментирован без подмены логики приложения. После выбора неправильного пятинотного варианта зафиксировано 10 звуковых onset: пять для выбранной последовательности и пять для правильной. Относительные времена начала групп: `0, 529, 1048, 1565, 2087 ms`, затем `2723, 3251, 3768, 4293, 4811 ms`. При длительности последнего неправильного звука около `520 ms` правильная последовательность началась примерно через `116 ms`, то есть наложения не было. Основные частоты первой ноты различались: неправильная `87 Hz`, правильная `78 Hz`; остальные четыре позиции совпали в конкретном дистракторе.

Это доказывает фактический порядок вызовов Web Audio в интегрированном приложении, но не является измерением акустического сигнала после ОС, усилителя и динамиков. Физическая слышимость конкретного устройства вывода остаётся вне программного acceptance.

### Энгармонические унисоны

Генератор проверяет фактический MIDI после применения ключевых и написанных случайных знаков. Автотест перебирает длины 1–5, все 15 ключевых сигнатур от семи бемолей до семи диезов и target с каждым distractor. Соседние `E–Fes`, `F♯` по ключу–`Ges` и другие энгармонические унисоны отбрасываются; возвращение к той же высоте через одну или несколько других нот разрешено. Отдельный regression-набор `melody.test.ts` прошёл: 12/12.

## Дополнительная контрактная проверка — 2026-08-26

- Подсказки больше не копируются в snapshot вопроса: текущий UI читает live `hints`, а их переключение не устанавливает маркер «применится дальше». Содержательные параметры и auto-advance по-прежнему применяются только к следующему вопросу.
- Карта ответа показывается по условию наличия результата, включая состояние неверного keyboard-ответа. Корректирующий ввод остаётся обязательным, а кнопка следующего вопроса в этом состоянии не появляется.
- Production keydown для target `sound` использует тестируемое решение `soundChoiceKeyboardAction`: цифры только прослушивают индекс варианта, `Enter` подтверждает только существующий активный вариант; многозвучные последовательности не сводятся к одному MIDI.
- `SequencePlayback.cancel()` теперь отменяет будущие ноты и останавливает активные голоса именно своей последовательности. Тесты подтверждают немедленный Web Audio stop, один MIDI note-off без отложенного дубликата и независимость параллельной последовательности.
- Слуховой source сообщает `onPresented` только из callback фактического onset. Для running Web Audio и успешного MIDI note-on callback вызывается один раз; delayed resume откладывает его, rejected resume и cancel-before-resume не вызывают его. `RepresentationView` отдельно проверен на отсутствие преждевременного `onPresented`.

После интеграции этих изменений полный `npm test` прошёл: 37 core + 77 web. `npm run build` прошёл; сохранено только прежнее предупреждение о размере динамического OSMD chunk.

# Ручная проверка MIDI и Android

Статус: обязательный внешний acceptance для функций, которые нельзя подтвердить только unit-тестами. Используется опубликованная версия [GitHub Pages](https://m0003r.github.io/musictrainer/). Результат каждого пункта фиксируется как `pass` или как наблюдение с моделью устройства, браузером и точным текстом статуса.

## MIDI IN

Предусловия: поддерживаемый браузер, подключённая MIDI-клавиатура, создан локальный профиль `MIDI QA`.

1. Открыть настройки и нажать «Подключить». Браузер должен запросить доступ только после этого действия.
2. После разрешения интерфейс должен показать имя выбранного входа. Разрешение без устройства должно показывать «Доступ есть, устройство не найдено», а не «Подключено».
3. Нажать ноту на физической клавиатуре. Статус должен показать последний принятый MIDI-номер; нажатие должно сопровождаться экранным звуком только согласно выбранному способу воспроизведения.
4. Выбрать направление с целью «Клавиатура», сначала одну ноту, затем пять. MIDI должен собирать ответ по порядку и показывать прогресс `n/5`; лишняя или неверная высота участвует в ответе, а не игнорируется.
5. После неверного ответа карта четырёх представлений должна быть видна сразу. Следующий вопрос остаётся заблокирован до правильного повторного ввода всей последовательности; коррекция не создаёт вторую попытку.
6. Выбрать направление с целью «Звучание». MIDI должен вводить последовательность напрямую; экранные звуковые карточки при этом сохраняют двухшаговый режим «прослушать → подтвердить».
7. Если входов несколько, переключить выбранное устройство. Имя и последняя нота должны обновиться; сообщение со старого входа после переключения не должно приниматься.
8. Отсоединить и снова подключить устройство без перезагрузки страницы. Статус должен измениться, hot-plug — повторно открыть доступный вход, приложение не должно зависнуть или потерять текущий пример.

## MIDI OUT

Предусловие: MIDI-устройство предоставляет выходной порт.

1. При доступном выходе выбрать «MIDI OUT» и конкретное устройство. MIDI IN при этом должен продолжать принимать ответы.
2. Прослушать исходный звук, варианты target `sound`, неправильную и правильную последовательности и ручные кнопки повтора. Все они должны идти через выбранный MIDI OUT.
3. Во время длинной последовательности нажать «Следующая связь». Текущая нота должна немедленно получить note-off, будущие ноты не должны прозвучать.
4. Отсоединить MIDI OUT. Интерфейс должен безопасно вернуться к Web Audio и явно показать отсутствие выхода; MIDI IN не должен отключаться.

## Android Chrome / PWA

Предусловия: Android-планшет, Chrome, доступ к опубликованному HTTPS URL.

1. Открыть сайт, создать профиль `Android QA`, изменить настройки и выполнить несколько попыток.
2. Установить сайт через доступное в Chrome действие добавления/установки. Иконка должна появиться на домашнем экране.
3. Запустить с домашнего экрана. Приложение должно открыться без адресной строки в standalone-режиме и предпочитать landscape.
4. Проверить, что профиль `Android QA`, настройки и накопленные попытки сохранились: установленное приложение должно использовать тот же origin, а не новый пустой профиль.
5. На landscape viewport убедиться, что задача, варианты и основное действие имеют приоритет; настройки открываются drawer-панелью, а страница не получает горизонтальную прокрутку.
6. После первой полной online-загрузки закрыть приложение, отключить сеть и открыть снова. Должны загрузиться shell, стили, основной JS, OSMD и уже сохранённые локальные профили.
7. Вернуть сеть, дождаться следующей публикации и открыть приложение повторно. Обновление service worker не должно стирать локальные профили или блокировать обычный запуск при ошибке регистрации.

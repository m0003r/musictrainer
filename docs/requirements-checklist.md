# Проверяемый список требований

Статусный документ для разработки, аудит `main` ревизии `a6a1e00` от 2026-08-25. `[x]` означает, что найден код и автоматическая проверка, а для пользовательского поведения — также зафиксированная ручная Firefox-проверка, где она применима. `[ ]` означает отсутствие функции или обязательного доказательства; частичные результаты не превращают составной пункт в выполненный. Подробные результаты: [acceptance-2026-08-25.md](acceptance-2026-08-25.md).

## Цель обучения

- [x] Тренажёр связывает четыре представления одной и той же музыкальной сущности: нотную запись, название, положение на фортепианной клавиатуре и звучание.
- [x] Все четыре представления участвуют в общей системе упражнений, а не в четырёх несвязанных режимах.
- [ ] Цель — мгновенное узнавание и преобразование без внутреннего вычисления; улучшение после практики может быть постепенным.
- [x] Основная аудитория — взрослый человек, который хочет играть по нотам, но после перерыва опирается преимущественно на хороший слух и может подбирать знакомое на слух.
- [x] Продукт поддерживает самостоятельную практику между уроками.
- [x] Учитывается наблюдаемое преподавателем явление: игра знакомого материала по слуху во время перерыва может сопровождаться ослаблением чтения; это не подменяет общую цель тренажёра.

Пункт о мгновенном преобразовании остаётся открытой учебной целью: наличие тренажёра и краткий acceptance-прогон не доказывают педагогический результат.

## Матрица упражнений

- [x] Поддерживаются все 12 направленных связей между четырьмя разными представлениями.
- [x] Пользователь независимо отмечает галками «Что дано» и «Что отгадываем»; хотя бы одна валидная связь всегда остаётся.
- [x] Тест с выбором готового варианта доступен как текущий промежуточный способ ответа.
- [x] В одном примере можно выбрать от 1 до 5 последовательных нот.
- [x] Отдельно настраивается максимальное расстояние между соседними нотами последовательности.
- [ ] Последовательность работает во всех четырёх представлениях, во всех вариантах ответа, в обратной связи и при MIDI-вводе. — Код и unit-тесты есть; физический MIDI-ввод не проверен (`manual hardware`).
- [x] Последовательности пока имеют равные длительности и не объявляются упражнением на ритм.
- [x] Изменение содержательных настроек не меняет уже показанный пример; новые настройки применяются со следующего примера.

## Сложность и геймификация

- [x] Есть явно видимый регулятор уровня сложности.
- [x] Каждый уровень можно гибко донастроить: диапазон и добавочные линейки, число вариантов, расстояние дистракторов, число нот, мелодический ход, ключевые и случайные знаки.
- [x] Низкие уровни не предлагают соседние ноты в качестве дистракторов.
- [x] Есть документированная лестница сложности для геймификации, от опорных нот до свободного чтения со знаками и несколькими нотами.
- [x] Статистика не создаёт ложного обещания «мгновенного чтения» после короткой практики.

Weighted contour grammar в текущем генераторе — implementation/product hypothesis pending teacher approval, а не универсальный закон. Подтверждённое правило отдельно: после ключевых и написанных случайных знаков соседние ноты target и distractors не могут быть энгармоническим унисоном; повтор высоты позже допустим.

## Нотная запись и названия

- [x] Нотная запись рендерится через OSMD во всех семи поддерживаемых ключах; Firefox-прогон подтвердил по 6 карточек без переполнения для каждого ключа.
- [x] Ключи выбираются списком с галочками.
- [x] Размер не печатается на каждом стане и каждом примере.
- [x] Нотоносец достаточно длинный для семи ключевых знаков, случайного знака и до пяти нот; ничего не выходит за правую границу карточки.
- [x] Поддерживаются ключевые знаки от семи бемолей до семи диезов.
- [x] Поддерживаются явно напечатанные случайные бемоль, бекар и диез.
- [x] Для ноты со случайным знаком среди вариантов обязательно есть контекстное различение той же ступени и октавы со знаком, действующим по ключу; например, для ре-бекар при бемольной тональности есть ре-бемоль той же октавы.
- [x] После применения ключевых и написанных случайных знаков соседние ноты target и каждого distractor различаются по MIDI-высоте (`e–fes` и `F♯` по ключу–`Ges` запрещены); несоседний повтор высоты допустим.
- [x] Названия одновременно показываются во всех поддерживаемых системах: русские слоги и немецкая буквенная система.

## Фортепианная клавиатура и подсказки

- [x] Все видимые белые и чёрные клавиши экранного фортепиано нажимаются в режиме ответа.
- [x] Клавиатура использует доступную ширину большого экрана и не получает ненужный горизонтальный scroll.
- [x] На узком экране клавиатура остаётся доступной без переполнения всей страницы.
- [x] Названия октав на клавиатуре включены по умолчанию.
- [x] Можно включить подписи нот на клавишах.
- [x] Можно включить справочник с опорными нотами и направлением счёта для скрипичного, басового и остальных ключей.
- [x] Для последовательности понятны порядок и прогресс ввода нот.

## Звук и обратная связь

- [x] Даже задания «на глаз» вызывают акустическую обратную связь через выбранный программный выход; это подтверждено тестами и инструментированием Web Audio в Firefox.
- [x] При неверном выборе сначала запускается выбранный неправильный ответ, затем правильный, без наложения; порядок подтверждён по фактическим временам `OscillatorNode.start()` в Firefox.
- [x] Для последовательности целиком запускается неправильная последовательность, затем правильная: в проверке пяти нот зафиксированы две группы по пять звуков.
- [x] После ответа доступны ручные кнопки повторного прослушивания своего и правильного ответа; обработчики и teardown покрыты тестами. Физическая слышимость конкретного устройства вывода не утверждается этим программным аудитом.
- [x] Настройка «Автопереход через 1 секунду» по умолчанию выключена.
- [x] При включённой настройке только верный ответ автоматически открывает следующий пример через 1 секунду; ручной переход остаётся доступным.
- [x] Таймер автоперехода отменяется при ручном переходе, размонтировании и создании другого примера.

## MIDI

- [ ] MIDI-ввод является полноценным основным способом ответа для клавиатурных и звуковых заданий. — Реализация и unit-тесты есть; требуется `manual hardware`.
- [ ] Подключение запрашивается явным действием пользователя и показывает понятный статус, ошибки, имя устройства и последнюю принятую MIDI-ноту. — Требуется `manual hardware`.
- [ ] Работают устройства, требующие явного `open()`, все MIDI-каналы, note-on с ненулевой velocity и hot-plug. — Unit-тесты проходят; требуется `manual hardware`.
- [x] Note-on с velocity 0 не считается новой нажатой нотой.
- [ ] Для 2–5 нот MIDI последовательно собирает ответ и показывает прогресс. — Требуется `manual hardware`.
- [ ] Есть переключатель воспроизведения через Web Audio или MIDI OUT; недоступный MIDI OUT не выбирается молча. — Web Audio и routing покрыты тестами; физический MIDI OUT требует `manual hardware`.

## Локальная работа и публикация

- [x] Приложение в первую очередь работает локально и не требует сервера или сетевого соединения после загрузки статики.
- [x] Вместо логина и пароля используются локальные профили только с именем, как в играх.
- [x] Профили, активный профиль, попытки, прогресс и пользовательские настройки хранятся в версионированном localStorage.
- [x] Ошибка или недоступность localStorage обрабатывается понятным сообщением без потери текущего упражнения.
- [x] Production build работает как статический сайт с относительными asset URL и может быть опубликован на GitHub Pages.
- [ ] На Android в Chrome сайт соответствует installability-критериям PWA: manifest связан со страницей, указаны name/short_name/start_url/display, есть raster icons 192×192 и 512×512, зарегистрирован service worker и используется HTTPS при публикации. — Статика и тесты есть; требуется `manual Android install`.
- [ ] Установленный с домашнего экрана тренажёр запускается в standalone-режиме преимущественно в landscape и продолжает видеть те же локальные профили своего origin. — Требуется `manual Android home-screen`.
- [x] При отсутствии или ошибке service worker обычная работа сайта не блокируется.
- [x] Runtime frontend не обращается к `/api/*`; backend не нужен для основного приложения.
- [x] Совместимость со старыми dev-схемами пока не требуется.

## UX и адаптивность

- [x] Основной целевой сценарий — планшет в альбомной ориентации; ключевые действия и экранная клавиатура помещаются без лишней прокрутки примерно при 1024×768 и 1180×820.
- [x] На современных больших экранах интерфейс использует доступную площадь и не превращает основной тренажёр в узкую колонку.
- [x] Настройки компактны, но всегда обнаружимы; на мобильном экране они сворачиваются.
- [x] Текущая задача, варианты и основное действие имеют более высокий визуальный приоритет, чем служебные настройки и статистика.
- [x] Desktop 1600×900 и viewport 320 px не имеют горизонтального переполнения страницы; на узком экране широкая клавиатура прокручивается только внутри своего контейнера.
- [x] Ошибки, коррекция и выбранное состояние видны не только цветом: Firefox показал текст «Пока нет», описание ответа и инструкцию корректирующего нажатия.

## Методика и будущие этапы

- [x] DESIGN опирается на упражнения Хвостенко и явно отделяет подтверждённые требования преподавателя от продуктовых гипотез.
- [x] В roadmap включены продуктивные упражнения на запись нот, а не только распознавание и выбор готового варианта. — Это статус документации, не текущая функция.
- [x] Ритм зафиксирован как обязательное, но отдельное и более сложное будущее направление; текущая версия его не имитирует. — Это roadmap, не текущая функция.

## Доказательства готовности

- [x] Unit-тесты покрывают генерацию сложности, последовательности 1–5, ограничение интервала, дистракторы, знаки, MusicXML, localStorage, MIDI и автопереход.
- [x] Полный `npm test` проходит: 37 core + 67 web тестов на `a6a1e00`.
- [x] Полный production build проходит без runtime-зависимости от API.
- [x] Firefox-проверка выполнена на планшетных landscape viewport 1024×768 и 1180×820, большом desktop viewport 1600×900 и узком viewport 320 px.
- [ ] В Firefox проверены OSMD с семью знаками и пятью нотами, все клавиши, next-example-only settings, неверный→правильный Web Audio и автопереход; составной пункт остаётся открытым только из-за отсутствия проверки статуса с физическим MIDI-устройством.

- [ ] Android install/home-screen, standalone/landscape и сохранение локальных профилей origin проверены на устройстве. — Не выполнено, требуется `manual Android device`.

Итог аудита не является blanket `complete`: автоматические проверки и основные планшетные Firefox-сценарии прошли, но перечисленные ручные пробелы остаются открытыми.

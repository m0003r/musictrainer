# Проверяемый список требований

Статусный документ для разработки. Требование считается выполненным только при наличии кода, автоматической проверки там, где она уместна, и ручной Firefox-проверки пользовательского сценария.

## Цель обучения

- [ ] Тренажёр связывает четыре представления одной и той же музыкальной сущности: нотную запись, название, положение на фортепианной клавиатуре и звучание.
- [ ] Все четыре представления участвуют в общей системе упражнений, а не в четырёх несвязанных режимах.
- [ ] Цель — мгновенное узнавание и преобразование без внутреннего вычисления; улучшение после практики может быть постепенным.
- [ ] Основная аудитория — взрослый человек, который хочет играть по нотам, но после перерыва опирается преимущественно на хороший слух и может подбирать знакомое на слух.
- [ ] Продукт поддерживает самостоятельную практику между уроками.
- [ ] Учитывается наблюдаемое преподавателем явление: игра знакомого материала по слуху во время перерыва может сопровождаться ослаблением чтения; это не подменяет общую цель тренажёра.

## Матрица упражнений

- [ ] Поддерживаются все 12 направленных связей между четырьмя разными представлениями.
- [ ] Пользователь независимо отмечает галками «Что дано» и «Что отгадываем»; хотя бы одна валидная связь всегда остаётся.
- [ ] Тест с выбором готового варианта доступен как текущий промежуточный способ ответа.
- [ ] В одном примере можно выбрать от 1 до 5 последовательных нот.
- [ ] Отдельно настраивается максимальное расстояние между соседними нотами последовательности.
- [ ] Последовательность работает во всех четырёх представлениях, во всех вариантах ответа, в обратной связи и при MIDI-вводе.
- [ ] Последовательности пока имеют равные длительности и не объявляются упражнением на ритм.
- [ ] Изменение содержательных настроек не меняет уже показанный пример; новые настройки применяются со следующего примера.

## Сложность и геймификация

- [ ] Есть явно видимый регулятор уровня сложности.
- [ ] Каждый уровень можно гибко донастроить: диапазон и добавочные линейки, число вариантов, расстояние дистракторов, число нот, мелодический ход, ключевые и случайные знаки.
- [ ] Низкие уровни не предлагают соседние ноты в качестве дистракторов.
- [ ] Есть документированная лестница сложности для геймификации, от опорных нот до свободного чтения со знаками и несколькими нотами.
- [ ] Статистика не создаёт ложного обещания «мгновенного чтения» после короткой практики.

## Нотная запись и названия

- [ ] Нотная запись рендерится через OSMD во всех семи поддерживаемых ключах.
- [ ] Ключи выбираются списком с галочками.
- [ ] Размер не печатается на каждом стане и каждом примере.
- [ ] Нотоносец достаточно длинный для семи ключевых знаков, случайного знака и до пяти нот; ничего не выходит за правую границу карточки.
- [ ] Поддерживаются ключевые знаки от семи бемолей до семи диезов.
- [ ] Поддерживаются явно напечатанные случайные бемоль, бекар и диез.
- [ ] Для ноты со случайным знаком среди вариантов обязательно есть контекстное различение той же ступени и октавы со знаком, действующим по ключу; например, для ре-бекар при бемольной тональности есть ре-бемоль той же октавы.
- [ ] Названия одновременно показываются во всех поддерживаемых системах: русские слоги и немецкая буквенная система.

## Фортепианная клавиатура и подсказки

- [ ] Все видимые белые и чёрные клавиши экранного фортепиано нажимаются в режиме ответа.
- [ ] Клавиатура использует доступную ширину большого экрана и не получает ненужный горизонтальный scroll.
- [ ] На узком экране клавиатура остаётся доступной без переполнения всей страницы.
- [ ] Названия октав на клавиатуре включены по умолчанию.
- [ ] Можно включить подписи нот на клавишах.
- [ ] Можно включить справочник с опорными нотами и направлением счёта для скрипичного, басового и остальных ключей.
- [ ] Для последовательности понятны порядок и прогресс ввода нот.

## Звук и обратная связь

- [ ] Даже задания «на глаз» дают акустическую обратную связь.
- [ ] При неверном выборе сначала звучит выбранный неправильный ответ, затем правильный.
- [ ] Для последовательности целиком звучит неправильная последовательность, затем правильная.
- [ ] После ответа доступны ручные кнопки повторного прослушивания своего и правильного ответа.
- [ ] Настройка «Автопереход через 1 секунду» по умолчанию выключена.
- [ ] При включённой настройке только верный ответ автоматически открывает следующий пример через 1 секунду; ручной переход остаётся доступным.
- [ ] Таймер автоперехода отменяется при ручном переходе, размонтировании и создании другого примера.

## MIDI

- [ ] MIDI-ввод является полноценным основным способом ответа для клавиатурных и звуковых заданий.
- [ ] Подключение запрашивается явным действием пользователя и показывает понятный статус, ошибки, имя устройства и последнюю принятую MIDI-ноту.
- [ ] Работают устройства, требующие явного `open()`, все MIDI-каналы, note-on с ненулевой velocity и hot-plug.
- [ ] Note-on с velocity 0 не считается новой нажатой нотой.
- [ ] Для 2–5 нот MIDI последовательно собирает ответ и показывает прогресс.
- [ ] Есть переключатель воспроизведения через Web Audio или MIDI OUT; недоступный MIDI OUT не выбирается молча.

## Локальная работа и публикация

- [ ] Приложение в первую очередь работает локально и не требует сервера или сетевого соединения после загрузки статики.
- [ ] Вместо логина и пароля используются локальные профили только с именем, как в играх.
- [ ] Профили, активный профиль, попытки, прогресс и пользовательские настройки хранятся в версионированном localStorage.
- [ ] Ошибка или недоступность localStorage обрабатывается понятным сообщением без потери текущего упражнения.
- [ ] Production build работает как статический сайт с относительными asset URL и может быть опубликован на GitHub Pages.
- [ ] Runtime frontend не обращается к `/api/*`; backend не нужен для основного приложения.
- [ ] Совместимость со старыми dev-схемами пока не требуется.

## UX и адаптивность

- [ ] На современных больших экранах интерфейс использует доступную площадь и не превращает основной тренажёр в узкую колонку.
- [ ] Настройки компактны, но всегда обнаружимы; на мобильном экране они сворачиваются.
- [ ] Текущая задача, варианты и основное действие имеют более высокий визуальный приоритет, чем служебные настройки и статистика.
- [ ] Desktop и viewport 320 px не имеют горизонтального переполнения страницы.
- [ ] Ошибки, коррекция и выбранное состояние видны не только цветом.

## Методика и будущие этапы

- [ ] DESIGN опирается на упражнения Хвостенко и явно отделяет подтверждённые требования преподавателя от продуктовых гипотез.
- [ ] В roadmap включены продуктивные упражнения на запись нот, а не только распознавание и выбор готового варианта.
- [ ] Ритм зафиксирован как обязательное, но отдельное и более сложное будущее направление; текущая версия его не имитирует.

## Доказательства готовности

- [ ] Unit-тесты покрывают генерацию сложности, последовательности 1–5, ограничение интервала, дистракторы, знаки, MusicXML, localStorage, MIDI и автопереход.
- [ ] Полный `npm test` проходит.
- [ ] Полный production build проходит без runtime-зависимости от API.
- [ ] Firefox-проверка выполнена на большом desktop viewport и 320 px.
- [ ] В Firefox проверены OSMD с семью знаками и пятью нотами, все клавиши, next-example-only settings, неверный→правильный звук, автопереход и graceful MIDI status.

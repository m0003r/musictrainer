# Music Trainer

Веб-тренажёр для формирования устойчивых связей между четырьмя представлениями ноты:

1. нотная запись в разных ключах;
2. название ноты в разных языковых системах;
3. положение на фортепианной клавиатуре;
4. звучание.

Целевой первый срез — промежуточные упражнения с выбором ответа для взрослого ученика, у которого после перерыва наблюдается ослабление чтения при сохранённом подборе знакомого материала на слух. Контракт опирается на упражнения Хвостенко: все 12 преобразований, семь ключей, ключевые и написанные случайные знаки с контекстными дистракторами, последовательности из 1–5 равнодлительных нот с ограничением максимального движения, экранный и физический MIDI-ввод, а также воспроизведение через Web Audio или MIDI OUT. Продуктивная запись нот обязательна следующим этапом; ритм появится позднее как отдельная система.

Основное целевое устройство — планшет в альбомном режиме. Обязательные Firefox acceptance viewport — `1024×768` и `1180×820`; большой desktop и ширина `320 px` проверяются дополнительно. Названия октав на клавиатуре включены по умолчанию, содержательные настройки действуют только со следующего примера, а опциональный автопереход открывает новый пример через одну секунду только после правильного ответа.

Целевая публикация — статический PWA на GitHub Pages с относительными asset URL. Профили только локальные: имя, активный профиль, попытки, прогресс и настройки хранятся в версионированном `localStorage`; backend и сеть после первой загрузки статики не нужны. Репозиторий находится в разработке: существование кода или описания не означает выполнения требования. Актуальный статус находится в [проверяемом списке требований](docs/requirements-checklist.md), а воспроизводимые автоматические и Firefox-результаты — в [acceptance за 2026-08-25](docs/acceptance-2026-08-25.md).

Подробности: [продуктовый контракт](docs/product-contract.md), [дизайн](docs/design.md), [связь с упражнениями Хвостенко](docs/khvostenko-evidence.md), [лестница сложности](docs/difficulty-ladder.md), [продуктивная запись](docs/productive-note-entry.md), [накопленные вопросы](docs/open-questions.md).

## Запуск

Требуется Node.js 20.19 или новее.

1. `npm install`
2. Запустить frontend: `npm run dev`
3. Открыть `http://localhost:5173`

Проверки: `npm test` и `npm run build`. Результат сборки находится в `apps/web/dist` и не требует Node.js-сервера.

В целевом сценарии при первом открытии достаточно создать профиль по имени, как игровой слот сохранения. Email и пароль не нужны; любой профиль можно выбрать в этом браузере. Совместимость со старыми dev-схемами пока не требуется.

## Установка на Android

Заявленный сценарий: после публикации по HTTPS открыть сайт в Chrome и выбрать «Установить приложение» или «Добавить на главный экран». Manifest запрашивает отдельное окно и альбомную ориентацию, а профили остаются локальными для origin GitHub Pages. Фактическая установка и запуск с домашнего экрана Android ещё не проверены вручную и остаются открытым acceptance-пунктом.

## Публикация

Push в `main` автоматически проверяет и разворачивает свежую сборку на GitHub Pages. Tag вида `v1.0.0` запускает release-flow: тестирует проект, создаёт GitHub Release с архивом статического bundle и публикует тот же bundle на Pages. Для репозитория нужно один раз выбрать GitHub Actions как источник Pages в Settings → Pages.
